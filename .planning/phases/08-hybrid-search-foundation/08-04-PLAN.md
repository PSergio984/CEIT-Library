ASVS L1. Block on HIGH severity threats.

| Threat | Severity | Mitigation in this plan |
|---|---|---|
| T-01 Sidecar token written into code or logs (R4) | HIGH | Token only via `config('services.ai_sidecar.token')` (env-backed, `.env` gitignored); `AiServiceAuthException` messages carry NO token; service never logs the token or request headers. |
| T-02 SSRF via misconfigured `SIDECAR_URL` | MED | Default `SIDECAR_URL` is `http://127.0.0.1:8310` (loopback); base_url is admin-controlled env config, documented in `.env.example` comment; no user input ever influences the URL. |
| T-03 User queries (may contain names) forwarded to sidecar without hygiene | LOW | Queries are search terms to a loopback service; Laravel logging already sanitized by `PiiSanitizerProcessor`; `AiService` must not `Log::info()` query or response bodies. |
| T-04 Sidecar down wedges Livewire/Octane request (hung HTTP) | MED | Per-call fresh `Http` client (no pooled state, R12), `connectTimeout(3)`, `timeout(10)`, retries bounded (`retry(2, 250, throw: false)` on /search only); failures raise typed exceptions for the UI fallback path (08-05). |
| T-05 Availability decided by model | LOW | `AiService` returns no availability data this phase (D-04) — availability stays DB-side; nothing to fake here. |
</threat_model>
