<objective>
Build the Laravel side of the corpus export pipeline: a pure serialization service (`CorpusExporter`) that converts `AcademicPaper` (+ authors, advisers, dean) and `RuleHeader`/`RuleRegulation` rows into the JSON document shapes locked in 08-RESEARCH.md §2.2, plus the `ai:export-corpus` artisan command that writes `catalog.json` / `policies.json` to `storage/app/ai-corpus/`, plus feature tests pinning the schema, anti-PII guarantees, and edge cases.

Purpose: The export is the single source of truth the sidecar ingests (D-12/D-17) and the input to the golden set (D-19). Every later plan (sidecar ingest, sync jobs, reconcile) depends on this contract. Success criterion 3 of the phase (`ai:export-corpus` reproduces the corpus JSON) is proven here.

Output: `CorpusExporter` service, `ExportAiCorpus` command, `ExportAiCorpusTest` feature tests, and two JSON files on disk when the command runs.
</objective>

<threat_model>
ASVS L1. Block on HIGH severity threats. This plan introduces the corpus export path — new outbound data flow (DB → JSON files on disk).

| Threat | Severity | Mitigation in this plan |
|---|---|---|
| T-01 Export leaks borrower/user PII (borrows, users, attendance, emails) | HIGH | Exporter queries ONLY `AcademicPaper`, `RuleHeader`, `RuleRegulation`, `Author`, `ResearchAdviser`, `TechnicalAdviser`, `Dean`. `ExportAiCorpusTest` asserts the serialized JSON contains no `copy_number`, `status`, `email`, or user-account keys. Corpus dir is `storage/app/ai-corpus/` (never web-served). |
| T-02 Document contents leak into logs (PiiSanitizerProcessor gap) | MED | Exporter/command must NEVER call `Log::info()` with document contents; only counts and paths are logged. |
| T-03 Prompt-injection payloads ride untruncated librarian-editable text into the future index | MED | Field caps enforced at export: title ≤ 500, names ≤ 200, regulation content ≤ 20000; control chars (`\x00-\x1F`, `\x7F`) stripped; whitespace collapsed. |
| T-04 `RuleHeader::ruleRegulations()->orderBy('order')` crashes on a missing `order` column (R10) | LOW | Exporter uses `->orderBy('id')` on regulations; a comment flags the latent bug for a future fix outside phase scope. |
</threat_model>

  - Private `sanitize(?string $value, int $maxLen): string` — strip control chars `[\x00-\x1F\x7F]`, collapse whitespace, cap at `$maxLen` (title 500, names 200, content 20000).
  - NEVER `Log::info()` document contents; log counts only.
