ASVS L1. Block on HIGH severity threats.

| Threat | Severity | Mitigation in this plan |
|---|---|---|
| T-01 Deleted paper remains searchable (misinformation — trust killer per D-11) | HIGH | `deleted` observer events dispatch `AiIndexRebuildImmediateJob` (no delay, distinct unique id); `RuleRegulation`/people-model deletes same. Nightly reconcile is the safety net. Asserted in `AiIndexObserverTest`. |
| T-02 Unauthorized rebuild triggers from app → sidecar | MED | All rebuild calls flow through `AiService::rebuildIndex()` which attaches `X-Sidecar-Token`; sidecar 401s otherwise (08-02). |
| T-03 Rebuild failures silently swallowed (index rot) | MED | Jobs let exceptions propagate (`$tries = 3`, `$backoff = 60`, database queue → `failed_jobs` visible); `SyncAiIndex` returns exit 1 on `AiServiceUnavailableException`; reconcile logs `Log::warning` on mismatch (counts only, no document contents). |
| T-04 Reconcile/log output leaks catalog contents or token | MED | Reconcile logs expected/actual COUNTS and `source_generated_at` only; never doc bodies, never the token (PiiSanitizerProcessor already redacts email/QR patterns; this plan adds nothing sensitive). |
| T-05 Burst edits trigger rebuild storms | LOW | `ShouldBeUnique(uniqueId: 'ai-index-rebuild', uniqueFor: 300)` + 60s dispatch delay collapse bursts; immediate job uses a separate unique id so a pending debounced job cannot swallow a deletion rebuild. |
</threat_model>
