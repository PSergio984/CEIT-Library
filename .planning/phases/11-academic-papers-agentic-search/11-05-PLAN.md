STRIDE Threat Register:

| ID | STRIDE | Threat | Sev | Disposition | Mitigation in this plan |
|---|---|---|---|---|---|
| T-11-18 | Tampering | SSE frame parser fall-through: a frame-shaped data line (e.g. an activity envelope `{"t": ...}`) is decoded as a chunk and yields raw JSON into the answer bubble | MED | MITIGATE | `chatStreamFrames()` handles ONLY `event: activity` / `event: citations` line-pairs; all other lines keep today's exact decode path; `chatStreamEvents()` untouched; the back-compat test asserts raw-chunk yields on the SAME fixture (pitfall #1) |
| T-11-19 | Spoofing | Citations-frame payload tampering/shape drift: a malformed or non-array citations payload reaches the final bubble / persistence and breaks chips or `ai_messages.citations` | MED | MITIGATE | The frame payload is `json_decode`d and type-checked (is_array of arrays with the six ADR 0006 keys) before use; malformed → fall back to `companionCitations()` and persist the fallback; tests cover the malformed-frame path |
| T-11-20 | DoS | Activity slot markup hazard: a multi-line/whitespace-wrapped `wire:stream` element resurfaces the idle-bubble bug (W-3) — invisible ghosts or layout jank after each stream | MED | MITIGATE | The `activity` slot element stays on a SINGLE line with `empty:py-0 empty:invisible` (verbatim UI-SPEC markup); render asserted via the Livewire test on the slot element |
| T-11-21 | Tampering | Refusal-vs-error misrender: the fail-closed refusal rendered as an amber error bubble with Retry (wrong affordance — implies the system failed), or a real provider error rendered as a normal bubble (hides failure) | MED | MITIGATE | Refusal text arrives as NORMAL chunk frames and renders as a normal assistant bubble (test asserts no error bubble/Retry); `event: error` continues to throw `AiServiceProviderException` → existing amber bubble + Retry (taxonomy untouched, ADR 0004) |
| T-11-22 | Info disclosure | Activity lines leak tool internals (args, result ids, JSON) into the DOM | LOW | MITIGATE | Activity frame content is rendered as plain text in the slot — the frame payload is a single `text` string from the sidecar's static copy table; no args/results are ever emitted as activity frames (11-03) |

No HIGH-severity threat is left without a mitigation — nothing blocks this plan.
