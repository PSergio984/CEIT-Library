## Paper Search Tab

**Contract (D-04):** paper search is a persistent mode on the existing student `AcademicPaperIndex` page, composed exactly like the Phase 10 similar-books mode: mode flag + snapshot restore, status filter force-exit honored, shared card path untouched.

**Markup:** insert a daisyUI tab strip between the page header (`<div class="mb-6">` header block) and `<x-academic-paper-filters>`, following the existing repo pattern (`admin-advisers-deans.blade.php:32-53`):

```blade
<div role="tablist" class="tabs tabs-boxed mb-6 bg-base-200 w-max">
    <a role="tab" class="tab {{ ! $paperTabActive ? 'tab-active' : '' }}" wire:click="$set('paperTabActive', false)">Browse</a>
    <a role="tab" class="tab {{ $paperTabActive ? 'tab-active' : '' }}" wire:click="$set('paperTabActive', true)">Paper Search</a>
</div>
```

**Behavior:**
- New `public bool $paperTabActive = false` prop on `AcademicPaperIndex`; the two tabs are always visible and act as the switcher (no separate "Back" button — unlike similar-books, results stay in place).
- Entering/leaving the tab must NOT reset browse state: snapshot `search`, all filter props, `hybridResults`, `aiSearchFailed`, page, `sortBy` (mirror `recommendationsSnapshot`, `AcademicPaperIndex.php:378-434`); author/adviser props join the snapshot.
- Status filter force-exit (D-18 pattern): `updatedStatusFilter()` → `exitHybridMode()` unchanged — in paper tab it drops to the SQL path inside the tab; `updatedAuthorFilter()`/`updatedAdviserFilter()` must NOT exit hybrid mode (they are sidecar filters).
- Topic box: reuse the existing search input in the filters component; when `$paperTabActive`, placeholder swaps to the paper-tab copy above. The ≥3-char topic gate in `runHybridSearch()` stands for topic-only searches; author/adviser selections are standalone search axes (see S-4 fix) — with no usable topic, the selected name becomes the query (ADR 0011 name-as-query precedent), and the name filter still narrows the ranking. When BOTH author and adviser are set with no usable topic, **author takes precedence as the query** (both filters still narrow); when neither is set, the gate exits to the SQL list. Browse mode ships the search verbatim (byte-identical pre-S-4 payload); only the paper tab normalizes/derives the query. Author/adviser selects live in the same `academic-paper-filters` panel (see below) and apply in both modes — but only route to the sidecar in paper-tab mode (composition matrix, RESEARCH.md).
- Results rendering: zero changes — the existing mobile card list / desktop hybrid grid / desktop table paths render hybrid results as today. No new sort control (D-06); the relevance caption replaces any sort affordance.
- The `wire:loading` targets list must add `paperTabActive, authorFilter, adviserFilter` to the existing "Updating results..." overlay targets so tab switches and author/adviser changes show the localized overlay.

## Filter Controls

**Contract (D-05):** explicit controls for author, adviser, and year range + the free-text topic box. Use the page's actual existing pattern — daisyUI-native selects with Alpine `x-for` options (`academic-paper-filters.blade.php:93-129`) — NOT `x-mary-select`:

```blade
<select wire:model.live="authorFilter" class="select select-bordered select-sm sm:select-md w-full">
    <option value="">All Authors</option>
    <template x-for="author in availableAuthors" :key="author">
        <option :value="author" x-text="author"></option>
    </template>
</select>

<select wire:model.live="adviserFilter" class="select select-bordered select-sm sm:select-md w-full">
    <option value="">All Advisers</option>
    <template x-for="adviser in availableAdvisers" :key="adviser">
        <option :value="adviser" x-text="adviser"></option>
    </template>
</select>
```

**Recommendation (prescriptive):** dropdown selects, not free-text inputs — authors/advisers are normalized FK tables (`Author`, `research_advisers`/`technical_advisers`), exact names are what the sidecar substring filter matches, and the page already models every filter as a select. The dropdown avoids typo-missed results and matches the existing 5-control row.

**Data sources:** `#[Computed] availableAuthors()` = `Author::distinct()->orderBy('name')->pluck('name')`; `availableAdvisers()` = union of `ResearchAdviser` + `TechnicalAdviser` names, distinct, ordered (RESEARCH.md §Recommended structure 7). Both follow the existing `#[Computed(persist: true, cache: true)]` pattern of `availableYears`/`availableDepartments` (`AcademicPaperIndex.php:188-224`).

**Layout:** keep the grid `grid-cols-1 sm:grid-cols-2 lg:grid-cols-5 gap-3`; append the two new selects after Department, so controls read: Status, Type, Department, Author, Adviser, Year From, Year To — the two new controls wrap onto a second row at `lg` (minimal diff, no grid rework). Add Alpine `validYearsFrom`/`validYearsTo` behavior untouched.

**Active-filters row:** extend the existing `hasActiveFilters` getter + badge row (`filters.blade.php:21-23, 133-155`) with `authorFilter`/`adviserFilter`: badges `Author: {name}` / `Adviser: {name}` with the same `badge badge-sm` styling. The Clear button (`clearFilters()`) must also reset the two new props.

## Agentic Loop Activity Lines

**Contract (D-12):** one compact, muted line per loop step, streamed into a second persistent Livewire stream slot above the answer slot; final answer streams normally with numbered citations; no raw tool JSON anywhere.

**Markup** (second W-3 slot — HAZARD: single-line persistent element, `:empty` collapse, same rule as the `ans` slot, `chat-widget.blade.php:67-83`):

```blade
<div class="flex justify-start">
    <div class="bg-base-200 text-base-content rounded-2xl rounded-bl-sm px-4 max-w-[85%]">
        <div wire:stream="activity" class="text-xs py-2 empty:py-0 empty:invisible space-y-1"></div>
    </div>
</div>
```

Mounted immediately above the existing `ans` slot, inside the same assistant-side column; the `:empty` collapse keeps it zero-height while idle (live CSS state, snaps open on first frame — identical to W-3).

**Streamed line shape:** each `event: activity` frame renders one line, server-streamed as HTML into the slot:

```html
<div class="flex items-center gap-1.5 py-0.5">
  <span class="loading loading-spinner loading-xs text-primary"></span>
  <span>Searching papers by author…</span>
</div>
```

- Typography: `text-xs`, `text-base-content/60` (muted), `gap-1.5` between spinner and copy — matches the existing caption style ("Checked just now", "Grounded in catalog + rulebook").
- Indicator: daisyUI `loading loading-spinner loading-xs text-primary` — `primary` is permitted here because it is the loading-indicator role the page already uses (`loading-spinner loading-lg text-primary` in every overlay). Do NOT use the bounce-dots for lines.
- One line per step, appended (frame order preserved); the final re-render wipes the slot when the answer bubble lands.

**Widget wiring:** in `ChatWidget::streamQuestion()`, on agentic path: immediately stream the existing bounce-dots markup (`ChatWidget.php:164-168`) into the `activity` slot (masks the first-call latency, RESEARCH.md A-4); `activity` frames → `$this->stream($line, false, 'activity')`; `chunk` frames → existing `'ans'` slot (dots no longer needed in `ans` on the agentic path — activity slot carries progress); `citations` frame → payload for the final bubble with `companionCitations()` fallback. Back-compat: non-agentic streams keep today's behavior untouched.

**Error state:** loop failure surfaces through the existing `event: error` taxonomy → `AiServiceException` → the existing amber error bubble + `Retry` (`chat-widget.blade.php:56-61`); the activity slot simply re-renders away with the bubble. Fail-closed refusal (D-08) is a normal assistant bubble with the canonical copy — not an error bubble, no Retry.

## Empty / Loading / Error States

| State | When | Contract |
|-------|------|----------|
| Idle prompt | Paper tab active, no topic, no author/adviser filter, no hybrid results | `<x-empty-state icon="o-magnifying-glass" title="Search the paper collection" message="Type a topic, or choose an author or adviser to find papers." :show-action="false" size="sm" />` — replaces the result area in paper-tab mode |
| No results | Paper tab, hybrid results empty (topic or filters set) | Reuse existing: `<x-empty-state icon="o-document-magnifying-glass" title="No Academic Papers Found" message="No papers match your current search." :show-action="false" size="sm" />` (mobile) / `size="default"` (desktop) |
| Loop running (page side, n/a — loop lives in chat) | — | Not applicable on the page; chat side is the activity slot (above) |
| Page search loading | `wire:target` includes `paperTabActive, authorFilter, adviserFilter` | Existing localized overlay: `absolute inset-0 bg-base-100/80 backdrop-blur-sm z-10` + `loading loading-spinner loading-lg text-primary` + `Updating results...` |
| Sidecar down (page) | `aiSearchFailed` in paper tab | Existing `alert alert-warning text-sm` — `AI search unavailable — showing basic results` (unchanged) |
| Sidecar down (chat) | `event: error` mid-loop | Existing amber bubble + `Retry` (unchanged); no partial activity lines remain after re-render |
| Fail-closed | Loop cap/malformed args, zero docs | Normal assistant bubble: `I don't have enough information` (ADR 0006 verbatim) — no error styling, no Retry |
