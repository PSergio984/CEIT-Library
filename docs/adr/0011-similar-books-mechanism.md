# Similar-books mechanism: title-as-query through the existing deterministic search

SEARCH-06 ("user can ask for 'books similar to X' and get recommendation results") is served by reusing the Phase 9 deterministic `/search` — no new sidecar endpoint, no embeddings math of its own. The catalog corpus is bibliographic-only (the doc embedding derives from title + metadata, `CorpusExporter`'s title-doubled text), so title-as-query carries the same signal cosine similarity would, and ADR 0006's determinism (same query/corpus/top_k → same ranked set) makes the recommendation set stable across renders.

**The mechanism is a Laravel service: `SimilarPapersService::for(AcademicPaper $paper, int $limit = 10): Collection<AcademicPaper>`.** It builds the query from **the paper's title only** — not authors, advisers, or department terms: author terms would bias toward "more by this author", and department/year/paper_type belong to filters, not the query string. It then calls `AiService::search()` **verbatim** — `corpus: 'catalog'`, `limit: 10` (same as the results page), `k` at the 60-candidate RRF pool constant — with **no metadata filters** (neither department nor paper_type): the doc text already carries X's metadata, so ranking self-selects affinity without over-constraining cross-department similarity.

**Self-exclusion is client-side by id.** The service maps the `paper-N` result ids, drops the seed paper's id, then loads the `AcademicPaper` models in sidecar rank order, returning the same collection shape the search page renders — so the caller reuses the existing cards, and the ADR 0010 hydrator feeds them through the shared card path. The RRF pool of 60 absorbs the one wasted rank slot, so no sidecar `exclude` parameter is needed (ADR 0004: prefer no new endpoint, no contract change).

**Empty case: fail closed, no fallback mechanism.** Sidecar down (`AiServiceUnavailableException`/`AiServiceAuthException`) → the service returns an empty result with an availability flag; the caller renders "Recommendations unavailable right now". Empty retrieval, or self-exclusion leaving nothing, → empty collection; the caller renders the empty state ("No similar books found"). There is no SQL fallback — a keyword-overlap SQL path would be a second, quality-inconsistent mechanism — and no LLM fallback — SEARCH-06's "recommendation results" is a deterministic list, never an LLM answer (the map's fog keeps chat interception of "similar to X" routed through this same mechanism for the same reason).

_Considered (rejected):_ a dedicated embedding-cosine `/similar` sidecar endpoint (the map records it as the upgrade path if quality testing demands it, not pre-emptive); author/department terms in the query (bias toward same-author output); hard metadata filters (over-constrain, and one-line upgrade later if quality testing wants them — the sidecar already supports `filters`); a sidecar `exclude` parameter (contract change for one wasted rank slot); SQL/LLM fallback on sidecar failure (inconsistent quality / violates the list-not-answer rule).
