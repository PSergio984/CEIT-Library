# Borrow-seeded Personal recommendations and its privacy boundary

_(CEIT-Library #60, parent spec #57; builds on ADR 0027 and sidecar ADR 0015.)_

The Student Dashboard gains a "Recommended for you" shelf produced by `PersonalRecommendationsService::for(User $user, int $limit = 8)`. Seeds are the user's last 10 distinct borrowed papers (any status — started, completed, overdue all count), newest first by `COALESCE(time_in, created_at)`. Exclusions are every paper the user has ever borrowed, capped at the sidecar's 200 most recent; the client additionally rejects every borrowed id as defence in depth for the over-cap tail. The call is `AiService::recommend()` verbatim — same deterministic `paper-N` id mapping, rank-order hydration, and `unavailable` flag as ADR 0027's `SimilarPapersService`.

A user with no borrows is a **cold start**, not a failure: the service returns the **popular list** — most-borrowed papers in the last 90 days, widening to all time when the window is empty, ordered `count DESC, id ASC`, cached one hour as a list of paper ids (`recommendations.popular.v1`). The sidecar is not called on cold start. On sidecar failure the shelf still fails closed — empty list + `unavailable` flag, no SQL or LLM fallback — consistent with ADR 0027/0011: the list is a deterministic data list, never an LLM answer, and never surfaced through the Assistant.

**Privacy boundary.** Only `paper-N` ids cross to the sidecar — `seed_ids`, `exclude_ids`, `limit` are the whole request body. No user id, name, email, or any pseudonymous key is ever included; a Feature test asserts the raw request body contains none of the user's fields. This keeps the Borrower identity rule (ADR 0019 PII enforcement) intact: borrow history never leaves the app and never surfaces through the Assistant.

**Dashboard shelf UX.** The shelf is a lazy child component (`RecommendedForYou`) inside the already-`#[Lazy]` dashboard, so a slow sidecar never blocks the page. Four render states: populated ("Recommended for you"), cold start ("Popular right now" with a borrow-to-personalise hint — no taste-based claims, the corpus is synthetic), empty (`x-empty-state`), unavailable ("Recommendations unavailable right now"). Cards mirror the search page's recommendation cards (availability badge, catalog code, title, department/year/type, live "X of Y available" via ADR 0010 hydration, deep link `/academic-papers?paper=N`) but are not extracted — no shared card component exists and extraction is deferred.

_Considered (rejected):_ sending a pseudonymous user key to the sidecar — unnecessary for the current seed contract and it weakens the privacy boundary; a SQL or LLM fallback on sidecar failure — inconsistent with the fail-closed quality decision in ADR 0027; per-user caching of recommendations — borrow history changes often enough that a stale shelf is worse than a fresh query, and the privacy boundary is cleaner with nothing per-user stored; extracting a shared paper-card component now — wider refactor than this change warrants.
