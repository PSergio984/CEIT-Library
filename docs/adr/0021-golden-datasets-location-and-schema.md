# Golden datasets live as repo-tracked fixtures keyed by logical document keys

EVAL-01 needs golden datasets for all three corpora (catalog, papers, policy) including negative cases, and the dev database is faker-seeded — so datasets must survive both code review and data churn. Golden cases are **repo-tracked JSON fixtures under `tests/Fixtures/AiEval/golden/`, one file per corpus** (`catalog.json`, `papers.json`, `policy.json`), extending the existing `tests/Fixtures/ai-sidecar/` convention; runtime `storage/` paths are gitignored and would orphan eval assets from the code consuming them.

Each case: `{id, query, corpus, filters?, relevant_keys[], negative, expected_behavior, notes}` where **`relevant_keys` reference logical document keys — slugified title plus `catalog_code` where present — never DB or export row ids**, so identical content keeps its identity across re-exports and faker re-seeds break nothing silently. `negative: true` cases carry empty `relevant_keys` and `"expected_behavior": "refuse"`; retrieval cases expect the listed keys among the top-k hits.

**Sizing follows the survey** (`research/rag-eval-practices`): start with ~45–50 hand-curated cases total (≥20% negatives), seeded from the already-realized Phase 08 golden-mapping cases plus new papers-corpus coverage; every fixed production bug becomes a permanent case; grow toward 150+ before launch hardening. Each file carries a header (`version`, `against_export` snapshot hash); the harness warns on mismatch, and re-mapping is manual-on-warning plus quarterly review — no silent staleness, no automatic rewrite.

_Considered (rejected):_ **runtime storage under `storage/app/`** — gitignored, unversioned, invisible to review; **database seeds** — couples eval truth to the very faker data it must outlive, and blurs test-fixture vs production-schema concerns; **binding to exported row ids** (`paper-4`) — the Phase 08 stopgap: works until any re-export/re-seed reshuffles ids, then breaks every case at once; **auto-regenerating datasets from the corpus** — would measure only what the pipeline already contains and erase negative-case intent.
