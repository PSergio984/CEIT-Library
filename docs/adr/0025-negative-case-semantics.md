# Negative cases score deterministically: canonical refusal verbatim, citations absent

Golden negatives flow only through the answer path. They are **excluded from retrieval metrics entirely** (ADR 0022) — "did the index return junk" is already punished by precision on positive cases, and a negative query has no relevant set to score. Their entire contract lives at the answer level, and it scores **without any judge call in the passing case**: a negative case passes iff the assembled answer **equals the canonical refusal string verbatim** ("I don't have enough information") **and the citation payload is empty**. This check is deterministic because the system makes it so — the sidecar emits that fixed string with zero LLM calls when retrieval comes back empty, so exact-match comparison measures the pipeline, not model phrasing. No fuzzy tolerance, no near-refusal matching: anything else is a failure.

Failures get classified before they get reported: a negative case that produced a non-refusal answer costs **exactly one judge call**, not to rescore but to classify *what the answer wrongly claimed* into the ADR 0024 failure taxonomy for the report. Symmetrically, a positive case answered with the canonical refusal is a **deterministic false-refusal failure** — no judge call either. This reconciles ADR 0023's fourth dimension honestly: refusal correctness is implemented deterministically rather than as an LLM dimension; the judge's live dimensions are therefore three (grounding, citation support, completeness) for positive answers, plus the single failure-classifier call for broken negatives.

**Role-denied operational questions are not golden negatives.** ADR 0020 routes them to the same canonical refusal structurally, but the golden fixtures are deliberately role-less (student-baseline persona, ADR 0021); exercising the librarian gate belongs to Phase 12's own test-matrix planning. Conflating the two would let a broken Gate look like a broken corpus.

_Considered (rejected):_ **measuring negative queries through `/search`** (e.g., "no results above threshold") — the search API exposes rankings, not calibrated confidence thresholds, so any cutoff would be invented; **fuzzy/near-refusal matching** — the whole guarantee is that the pipeline emits one fixed string deterministically; loosening the match would measure nothing; **judge-scored refusal quality** — paying tokens to re-decide what string-comparison already settled; **adding a `role` field to fixtures** — drags Phase 12's authorization surface into Phase 13's datasets, coupling two specs that should evolve separately.
