# Sidecar chat endpoint contract: single streamed endpoint, three-code errors

Phase 9 chat goes through one endpoint — `POST /chat/stream` — the same path ADR 0002 locked, with a request/response contract that both the Laravel `AiService` and the widget compile against. No one-shot HTTP companion: `RagService.answer()` stays an internal test seam, never exposed over the wire. The `/rag` name is rejected — "chat" is the domain term (CONTEXT.md: Assistant).

Request: `{"query": str (required), "mode": "citations"|"question"|"rag" (default citations), "corpus": "catalog"|"policy" (optional; absent = both corpora), "top_k": int 1–50 (default 5)}`. Those four fields are the whole Phase 9 schema: no `temperature`/`model` fields (ADR 0001 keeps the model config-only server-side, and the prompts don't tune temperature), and **no history field — the request is single-turn**. CHAT-02 requires persistence, not model memory: Messages live in the Laravel DB (schema ticket "Design the conversation history schema"), the model never sees prior turns. A future `history: [{role, content}]` field in OpenAI message format (mirroring `RagService._messages()`) is reserved in the ADR only; it is out of Phase 9 scope.

Response: SSE — `data: <chunk>` lines per token, `data: [DONE]` terminator (ADR 0002 framing). Mid-stream provider failure emits `event: error` carrying JSON `{"code": "provider_error", "message": <safe generic text>}` — never the raw exception or class name; details go to server logs only.

> **Correction (2026-08-14, code review W-1):** chunk payloads are JSON-encoded on the wire — `data: {"c": "<delta>"}` — because raw text framing silently loses newlines (paragraph breaks) inside LLM deltas. The `[DONE]` terminator and the `event: error` line are unchanged; the Laravel parser decodes the envelope and passes raw text through for compatibility. The wire key `c` is a named constant on both sides (`AiService::SSE_CHUNK_KEY`, sidecar `CHUNK_KEY`).

Auth: the existing global `X-Sidecar-Token` middleware gates `/chat/stream` like every endpoint (token provisioned in the "Provision the chat provider key and tokens" ticket). The 401 body's error code changes from `invalid_request` to `auth_failed` — auth is not a validation error.

Error taxonomy, three codes total: 401 `auth_failed` (operator action: token mismatch), 422 `invalid_request` (validation — including a new server-side check that `corpus` is `catalog`, `policy`, or absent), stream `provider_error` (upstream failure mid-stream; distinguishing rate-limit vs 5xx vs LLM-key auth is deferred to Phase 14 with metrics/rate limits).

Laravel side: `AiService` gains `chatStream(string $query, ?string $mode = 'citations', ?string $corpus = null, int $topK = 5)` — the request-building inside `send()` is factored into a shared private helper; `chatStream()` POSTs `/chat/stream`, runs `throwUnlessOk` first (so 401/422 still throw before any streaming), and returns the streamed `Response`. The Livewire component consumes it via `Http::toStream()` and emits `$this->stream(content: $chunk, replace: false)` per chunk (ADR 0002). One new typed exception, `AiServiceProviderException`, is thrown when the consumer sees `event: error`; `AiServiceAuthException` and `AiServiceUnavailableException` are unchanged (422 stays under the Unavailable catch-all — unreachable when the app follows the contract).

_Considered (rejected):_ a one-shot `POST /chat` companion (no non-widget caller exists in Phase 9); sidecar-side corpus auto-detection (deciding whether a question is a Policy or Catalog question belongs to the widget, not the endpoint); multi-turn history now (no Phase 9 requirement demands model memory).
