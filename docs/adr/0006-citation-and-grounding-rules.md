# Citation and grounding rules: companion search for sources, empty-retrieval refusal

SEARCH-03 citations and SEARCH-04 grounding are pinned by two mechanics grounded in the endpoint contract (ADR 0004) and the prompt inventory (ADR 0003).

**Citation sources come from a companion `/search` call, not the stream.** ADR 0004's stream carries answer text only (a summary event was rejected when the endpoint contract was grilled). But retrieval is deterministic — `rrf_search` on a fixed index returns the same result order for the same query/corpus/top_k — so the Laravel layer issues one `AiService::search()` with the same `query`, `corpus`, and `top_k` as the chat call and builds the citation payload from the numbered results. Payload shape: `[{n, id, corpus, title, url, catalog_code}]` — `n` is the 1-based prompt doc number the `[N]` markers bind to, `id`/`corpus`/`title` identify the record, `url` is the link target (catalog only), `catalog_code` the catalog identifier (catalog only). The payload persists into `ai_messages.citations` (ADR 0005) so the CHAT-02 history view re-renders it. Cost: one cheap local hybrid search per chat message — no extra LLM call.

**Rendering is corpus-dependent because link targets are.** Catalog records have a real show route (`academic-paper.show`, `/academic-papers/{id}` — the corpus exporter already ships this as each catalog doc's `url`), so catalog citations render as link chips (title + `catalog_code` subtitle) pointing at the paper page. Policy records (RuleHeader/RuleRegulation) have no per-rule page — only `rules-and-regulations.index` — so policy citations render as non-link chips (header title); building rule show pages is out of Phase 9 scope. The numbered source list under the answer renders the **full list** — the numbered set the model worked from — rather than parsing the answer text for cited `[N]` markers (fragile against streamed text, and CONTEXT.md defines the source list as the unit rendered under the answer).

**Grounding short-circuits only on empty retrieval.** When `rrf_search` returns zero results, `/chat/stream` emits the canonical refusal — `I don't have enough information` — as the single chunk followed by `[DONE]`, with **no LLM call** (guaranteed SEARCH-04 behavior, zero token cost). No score threshold: BM25 raw scores are not comparable across queries or corpora, so a "low score → refuse" cutoff would be uncalibratable; for non-empty retrieval the model's prompt-based source-faithfulness instructions (ADR 0003) carry the enforcement, as they already do. The refusal string is locked verbatim — `I don't have enough information` — matching the ported prompts and CONTEXT.md.

**One grounding rule for both corpora.** Catalog Q&A and policy Q&A (CHAT-04) refuse identically with the canonical string. The policy surface is a corpus difference — answers cite rule numbers through the citations mode — not a different refusal posture; a distinct "not covered in the rulebook" string has no requirement behind it.

_Considered (rejected):_ a stream summary event carrying the source list (reopens the #19 Q3 decision — framing stays text-only); re-deriving citations from `/search` at history-view time instead of persisting (ADR 0005's `citations` column already exists and keeps history renders offline-stable); per-rule show pages for policy citation links (no Phase 9 requirement); a score-threshold refusal (BM25 scores incomparable); a distinct policy refusal string (single Grounding concept in CONTEXT.md).
