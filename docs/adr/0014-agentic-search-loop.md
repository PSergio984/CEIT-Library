# Agentic search loop contract (function-calling over /search)

CHAT-05 ("assistant runs agentic multi-step search when one-shot retrieval is insufficient") is implemented inside the sidecar as the new implementation of the EXISTING `/chat/stream` endpoint — no new endpoint, no toggle, no new history fields (ADR 0004/0005 stand). The loop is bounded, search-only, and fail-closed (D-07..D-12).

**Trigger (D-07):** the first LLM call of every `/chat/stream` request is a single non-streamed tool-eligible call (`tools=[SEARCH_TOOL]`, `tool_choice: "auto"`). Tool-use in the response IS the auto-detect — no classifier (an extra LLM call with its own failure mode). If the model returns content without tool calls, that content streams as the final answer (chunks envelope unchanged); if it emits a tool call, the loop starts. Existing `mode` values stay valid; the final-answer prompt reuses the ADR 0003 citations-mode prompt over the accumulated docs.

**Tool surface (D-09, D-10):** exactly one `search` function mirroring the closed `/search` contract — `query` (required, str), `corpus` (enum `catalog`|`policy`), `filters` (object with known keys `paper_type`/`department`/`publication_year`/`year_from`/`year_to`/`author`/`adviser`, string/integer values per ADR 0013), `top_k` (int 1..50). `additionalProperties: false` in the spec AND a pydantic model with `extra="forbid"` server-side: model output becomes search input, so args are validated before any execution. Search-only: no web, no mutations, no multi-agent (REQUIREMENTS.md Out of Scope).

**Loop and cap (D-11):** `MAX_TOOL_ROUNDS = 3` counts EXECUTED searches (initial retrieval + 2 refinements). Each round: validate args → `rrf_search(query, k=60, limit=top_k, filters=…, corpus=…, include_text=True)` (the same internal seam the old one-shot path used) → merge results into a doc set deduped by id → append assistant tool-call message + tool result → next call. Malformed args get ONE corrective feedback turn, then fail-closed. No HTTP-level retries on the stream (existing `retries: 0` posture).

**Fail-closed (D-08):** loop cap or error → answer grounded in whatever docs accumulated; zero docs accumulated → the canonical ADR 0006 refusal streamed WITHOUT an LLM call (zero-token path). Never guess, never a weaker ungrounded answer.

**Citations (ADR 0006 binding):** the agentic citation set IS the merged, deduplicated doc set, numbered 1..N in merge order — never a fresh one-shot companion search. Emitted as a dedicated `event: citations` frame; absent frame (direct-answer path) → Laravel falls back to the existing `companionCitations()`.

**SSE framing (discretion resolved, ADR 0002 additive):** two new EVENT types, never data-line envelopes (a `{"t": "activity"}` envelope would fall through the chunk decoder and render raw JSON into the answer): `event: activity` + `data: {"text": "…"}` (one compact line per step, static strings — no raw tool JSON, D-12) and `event: citations` + `data: [{n, id, corpus, title, url, catalog_code}]`. `[DONE]` and `event: error` semantics unchanged (ADR 0004); mid-loop provider failure → single `event: error` + `[DONE]`.

_Considered (rejected):_ a query-rewrite/refine helper tool (D-10 — single search tool only); per-corpus tools (one tool, `corpus` param); a loop-runtime in Laravel (the `openai` SDK, API key, and `rrf_search` seam already live in the sidecar — no PHP SDK, no duplicated key, ADR 0001 posture intact); a streamed first call (tool detection on a stream is fragile); a classifier trigger; history replay (single-turn contract stands; the loop threads its own internal tool messages, never a `history` field over the wire); HTTP retries on tool rounds (a retried round may double-search).
