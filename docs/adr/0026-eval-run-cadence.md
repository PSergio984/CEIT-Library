# Eval runs stay manual for v2.0; cadence automation is deferred to Phase 14

Both harnesses ship as developer-invoked artisan commands (`ai:eval-retrieval`, `ai:eval-answers` — ADRs 0022/0023), and in v2.0 they stay exactly that: **manual runs at meaningful moments** — before/after prompt changes, after index rebuilds or corpus re-exports, and when working an annotation queue. The expectation is documented rather than enforced: anyone merging changes to prompts, corpus exporters, or index config runs both commands first and reads the reports.

**No CI scheduling and no PR gate in this phase**, including for the token-free retrieval harness. Every golden run requires a live sidecar holding a built index plus an OpenRouter key inside the CI environment — service containers, secrets, and cost accounting that are precisely the Phase 14 workstream (OPS-01 metrics visibility, OPS-02 rate limits and cost guards). Scheduled judge spend before dashboards exist is recurring cost with no consumer; and gating merges on numbers we have deliberately not invented yet (ADR 0022) would produce arbitrary reds. The decision is explicitly time-boxed: wiring cadence, thresholds, and dashboard hooks into CI is part of Phase 14 planning, not forgotten.

_Considered (rejected):_ **nightly CI schedule now** — builds Phase 14's infrastructure early, paid for in secrets management and flaky-service maintenance before anyone reads the output; **retrieval-only PR gate** — still needs the live-indexed sidecar in CI, so it buys half the same infrastructure; **gating on pre-invented thresholds** — rejected already by ADR 0022; a gate without a baseline measures nothing but noise.
