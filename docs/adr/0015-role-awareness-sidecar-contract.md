# Role-aware depth rides a new `role` field in the sidecar chat contract

> Amends [ADR 0004](0004-sidecar-chat-endpoint-contract.md): the request schema gains one optional field.

Phase 12 (CHAT-03) needs the Assistant's answer depth to follow the caller's role while CHAT-06 keeps borrower PII away from the LLM entirely. We extend the ADR 0004 request schema with an **optional fifth field: `"role": "student" | "librarian"`, defaulting to `"student"` when absent; invalid values 422 as `invalid_request`** (same treatment as `mode`/`corpus`). Laravel computes the value from its own Gates before calling — `librarian-or-admin-access` semantics, so admin/super_admin send `librarian` and only students send `student` — and the sidecar uses it to shape one role-appropriate instruction line in the `SYSTEM_PROMPT` slot at both live message-construction sites (`agent.py` initial loop messages and `_stream_final_answer`; both must change together or the persona misses the final streamed answer). The sidecar never receives borrower data under either value, so the strict PII line is unchanged.

**Mode interplay:** `role` alters only the system slot; ADR 0003's three modes stay user-message templates and compose with either role untouched, as does the server-side recommendation overlay.

_Considered (rejected):_ **stuffing Laravel-assembled context into `query`** — zero diff cost, but the same string drives `rrf_search` ranking (retrieval pollution), lands verbatim in INFO logs, widens the prompt-injection surface inside the field every template labels `Query:`, and leaves no seam for future role-dependent retrieval; **a required field** — forces simultaneous migration of every caller for no safety gain over the least-privilege default; **free-text persona strings** — attacker-influenceable text one hop from the system slot and log bloat; **migrating request validation to pydantic** — the manual allow-list (`CHAT_ALLOWED_KEYS`) is the established pattern and adding a member is mechanical.
