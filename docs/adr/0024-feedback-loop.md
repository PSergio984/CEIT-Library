# Thumbs persist on messages; feedback reports and an annotation queue close the loop

EVAL-04's votes currently vanish into the sidecar's feedback file and stop there — and the widget loses its own rating state on every reload because `ai_messages` never stored it. We add a **nullable `rating` column to `ai_messages`** (set by the owner's latest thumbs action, amending ADR 0005): the message is the natural home for "its owner rated this", history view can finally re-render the user's own vote, and reporting gets a queryable source inside the boundary that owns the data. The sidecar JSONL keeps receiving exactly what it receives today — dual-write, no format change.

Reporting joins the eval command family as **`ai:eval-feedback {--since=} {--format=}`**: up/down totals overall, **per-corpus breakdown derived from the citation payload** (where citations carry a corpus; answers without citations are reported as uncategorized rather than guessed), and a weekly trend — console table plus the standard JSON artifact under `storage/app/ai-eval/runs/`. Mode breakdown is explicitly absent: mode was never persisted on messages (ADR 0005), and inventing retro-active attribution would be fabrication.

The tuning artifact is concrete per the survey pattern: **`ai:eval-feedback --annotate` emits a filtered annotation queue** of thumbs-down turns ordered oldest-first, each entry carrying question, answer, citations, and an empty `failure_label` from a fixed taxonomy (`retrieval-miss`, `wrong-corpus`, `stale-content`, `grounding-failure`, `citation-wrong`, `other`). Labeled entries whose fix ships become permanent golden cases under ADR 0021's every-fixed-bug rule; recurring label counts surface in the report header as candidates for future automated evaluator dimensions — promotion stays a human decision.

**Privacy posture (ADR 0019 alignment)**: reports show aggregate counts only; question/answer text appears exclusively in the local annotation artifact — the same class of human-review document as judge-run artifacts, gitignored under `storage/`, never in logs, metrics, or anything sent toward the sidecar or LLM. Nothing in this loop touches borrower data at all.

_Considered (rejected):_ **status quo (sidecar-file-only votes)** — cross-service file parsing for Laravel reporting violates the service boundary and loses rating state in the UI forever; **separate `ai_feedback` event table** — event-history of changed minds has no consumer, and "latest vote" is fully expressible as one nullable column; **automatic correlation between down-votes and failing golden cases** — with ~50-case sets and 1–3% feedback rates the join would be noise; humans bridging via labeled failures → golden cases is the survey's proven loop; **auto-promoting recurring failure labels to evaluator dimensions** — tempting automation that would let the eval stack drift without review; counts inform, humans decide.
